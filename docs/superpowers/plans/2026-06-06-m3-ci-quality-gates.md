# M3·A — CI/CD & Quality Gates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up an enforced CI quality gate (tsc + tests + eslint + build on every PR), a real ESLint setup, the critical Next.js security bump, and dependency/Node hardening.

**Architecture:** Three isolated commits — (1) the `next` 15.5.19 security bump verified in isolation, (2) flat-config ESLint that lints app code only, (3) the GitHub Actions workflow + Dependabot + Node pin. No new app logic; the workflow's first run + a browser smoke are the verification.

**Tech Stack:** GitHub Actions, ESLint 9 (flat config) + eslint-config-next + typescript-eslint, Next.js 15, Vitest, Postgres (not needed in CI).

**Source spec:** `docs/superpowers/specs/2026-06-06-m3-ci-quality-gates-design.md`

## Conventions & constraints (read once)

- **This is config/tooling — no new unit tests.** Verification = a **local pre-flight** (`npm run typecheck && npm test && npm run lint && npm run build`) before each commit, a **browser smoke** after the `next` bump (controller-driven), and the **workflow's first CI run** as the end-to-end proof.
- **Three isolated commits** so the load-bearing `next` bump is bisectable — do NOT bundle it with eslint/CI.
- Baseline today: 83 vitest tests pass, `tsc --noEmit` clean, `npm run build` succeeds. ESLint does **not** exist yet (`"lint": "next lint"` is a phantom). `next` is exact-pinned at `15.5.4`.
- **Postgres `coffee-pg` must be running** for the browser smoke (Task 1) only; CI itself needs no DB.

## Task 2: ESLint flat config + fix error-level violations

**Files:** Create `eslint.config.mjs`; Modify `package.json`, `app/login/page.tsx`, `app/signup/signup-form.tsx` (+ whatever `eslint` reports)

(`eslint-config-next` is already present from Task 1. `@eslint/eslintrc` provides `FlatCompat` — `eslint-config-next` still ships a legacy config that the bridge adapts. If `npm install` emits peer-dep ERRORS that block install, resolve by aligning versions; use `--legacy-peer-deps` only as a last resort and note it.)

- [ ] **Step 2: Create `eslint.config.mjs`.**
```js
import { dirname } from "node:path";
import { fileURLToPath } from "node:url";
import { FlatCompat } from "@eslint/eslintrc";
import tseslint from "typescript-eslint";

const compat = new FlatCompat({ baseDirectory: dirname(fileURLToPath(import.meta.url)) });

export default tseslint.config(
  // Global ignores MUST be a standalone object (flat config; .eslintignore is dead).
  // The vendored trees (.agents = ~197 files, .claude, .playwright-mcp) must be excluded.
  {
    ignores: [
      ".agents/**",
      ".claude/**",
      ".playwright-mcp/**",
      ".next/**",
      "node_modules/**",
      "coverage/**",
      "docs/**",
      "next-env.d.ts",
      "*.config.js",
      "*.config.mjs",
    ],
  },
  ...compat.extends("next/core-web-vitals"),
  ...tseslint.configs.recommended,
);
```

Record the exact error list; it is the deterministic work for this task. (If eslint tries to lint `.agents`/`node_modules`, the `ignores` are wrong — fix them first.)

- [ ] **Step 5: Fix the two `<a href>` violations.** Add `import Link from "next/link";` to each file. ## Task 3: CI workflow + Dependabot + Node/tsconfig hardening

**Files:** Create `.github/workflows/ci.yml`, `.github/dependabot.yml`, `.nvmrc`; Modify `package.json`, `tsconfig.json`

- [ ] **Step 1: Create `.github/workflows/ci.yml`.**
```yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: "npm"
      - run: npm ci
      - name: Type-check
        run: npm run typecheck
      - name: Test
        run: npm test
      - name: Lint
        run: npm run lint
      - name: Build
        run: npm run build
        env:
          AUTH_SECRET: "ci-build-placeholder-not-a-secret"
```
(No Postgres service: every test mocks `@/lib/db`; `next build` is force-dynamic with a lazy `pg.Pool` and reads no env at module scope. The dummy `AUTH_SECRET` only suppresses a next-auth-beta build warning — it is not a secret and must NOT go in GitHub Secrets. `npm run lint` is `eslint .` which exits non-zero on **errors** only; the exhaustive-deps warnings don't fail the build.)

- [ ] **Step 2: Create `.github/dependabot.yml`.**
```yaml
version: 2
updates:
  - package-ecosystem: "npm"
    directory: "/"
    schedule:
      interval: "weekly"
    open-pull-requests-limit: 5
  - package-ecosystem: "github-actions"
    directory: "/"
    schedule:
      interval: "weekly"
```

- [ ] **Step 3: Create `.nvmrc`.** File `.nvmrc` containing exactly:
```
20
```

- [ ] **Step 4: Add `engines` to `package.json`.** Add a top-level `"engines": { "node": ">=20" }` key (e.g. after `"private": true`).

- [ ] **Step 5: Harden `tsconfig.json` exclude.** Change `"exclude": ["node_modules", "scripts/restore-claude-env.sh"]` to `"exclude": ["node_modules", "scripts/restore-claude-env.sh", ".agents", ".claude", "docs"]` (forward guard so a future vendored `.ts`/`.tsx` can't silently break `tsc`).

- [ ] **Step 6: Local pre-flight (mirror what CI will run).** Run, in order: `npm run typecheck` (exit 0) · `npm test` (83 passed) · `npm run lint` (exit 0) · `npm run build` (succeeds). All green = CI will pass.

- [ ] **Step 7: Validate the YAML.** Run: `node -e "const f=require('fs');for(const p of ['.github/workflows/ci.yml','.github/dependabot.yml']){const s=f.readFileSync(p,'utf8');if(!s.includes('\t'))console.log(p,'no tabs OK');else throw new Error(p+' has tabs')}"` (YAML must not contain tab indentation).

- [ ] **Step 8: Commit.**
```bash
git add .github/workflows/ci.yml .github/dependabot.yml .nvmrc package.json tsconfig.json
git commit -m "ci: GitHub Actions (tsc+test+lint+build) + dependabot + node pin + tsconfig hardening"

Expect the `ci` job to pass all five steps in the runner. If it fails, read `gh run view --log-failed` and fix (most likely: a lock-file mismatch → re-run `npm install`; or an `ignores` gap → eslint lints a vendored file). This is the real validation that the gate works in a clean environment.

- [ ] **Step 4: Document branch protection (manual — token lacks `administration` scope).** In the PR body and/or a note: after CI is green, enable in GitHub → **Settings → Branches → Add branch ruleset / rule** for `main`: **Require status checks to pass** → select **`ci`**; **Require branches to be up to date before merging**. (Optionally require a PR review.) This makes the green checks actually block merges. *(The `gh` token here only has `repo`/`read:org`/`admin:public_key` — no `administration` — so this can't be scripted in this environment.)*
